# Pixiv Wallpaper

适用于 Windows 10 / 11 的 Pixiv 排行榜壁纸工具。无需登录，支持按计划更换壁纸、历史榜单、分辨率筛选、托盘运行和可选的自建镜像。

## 安装

使用 Windows 便携版时，将整个程序文件夹解压到当前用户可写的目录，运行 `PixivWallpaper.exe`。请保留同目录的 `_internal` 文件夹，不要只移动 EXE。

便携版自带运行时，无需安装 Python 或 uv。建议不要放在 `Program Files` 等需要管理员权限写入的目录。源码不包含可执行程序，需要按下文自行构建。

## 使用

1. 在“队列设置”中选择排行榜和榜单时间，默认为“今日”和“保持最新”。
2. 设置方向筛选和最低分辨率，方向默认为“无”。
3. 点击“队列下一张”，或在“定时更新”中设置 CRON。
4. 根据网络环境配置代理或镜像地址。
5. 按需开启“开机启动”。

窗口首次启动时居中显示；之后会记忆窗口位置和大小，并在显示器布局变化时调整到当前主屏幕范围内。最小化时窗口保留在任务栏；点击关闭按钮则隐藏到系统托盘。

支持自定义宽高，格式为正整数 `宽x高`，使用小写 `x` 且不含空格，例如 `2560x1440`。不接受缺项、零、负数、小数或大写 `X`。

修改排行榜、日期、分辨率、横/竖屏筛选、代理或镜像地址会取消旧任务，并在新配置有效后重新请求。修改 CRON、开机启动选项不会中断当前更新。网络任务串行执行，取消正在等待响应的请求可能需要等到响应或超时。代理地址无效时会显示网络设置错误，不会误报为发布日期读取失败。

### 排行榜与日期

支持今日、本周、本月、新人、受男性欢迎、受女性欢迎、原创和 AI 生成八种榜单。

- **保持最新**：每次更新重新获取 Pixiv 当前发布的一期，不会固定到保存设置时的日期。
- **指定日期**：通过日历选择并固定请求该期榜单。周榜、新人榜、原创榜按七天显示，月榜按三十天显示；选择的是区间结束日期，实际区间以 Pixiv 返回信息为准。

每次打开日历都会查询所选榜单的当前发布日期，成功后才能选择历史日期。可选日期上限由 Pixiv 决定，不按本地日期推算。查询失败时可以关闭重试，或选择“保持最新”。尚未发布、不可访问或返回日期不符时会报错，不会自动改用其他日期。

每次更新都会实时读取所选榜单的全部可用页面，不设固定页数上限。队列身份由排行榜类型和 Pixiv 实际发布日期组成；“保持最新”和恰好对应同一期的指定日期属于同一队列。队列改变时从第一张开始，同一队列内按榜单顺序进入下一张。无法使用的作品会跳过；全部失败时保留当前壁纸。程序不随机打乱，也不把不同队列中同一作品当作播放进度。

榜单、作品详情和分页信息每次都在线读取，以保持与当前 Pixiv 响应一致。处理后的壁纸缓存只避免重复下载原图，不改变榜单成员、作品可访问性或内容安全检查。作品删除或失去全年龄资格后会被跳过，即使本地仍有对应壁纸文件。缓存不提供离线选图。

### 筛选与显示

仅获取未登录可访问、平台标记为全年龄且敏感等级较低的静态插画，排除漫画、动图及 R-18 / R-18G 内容。平台标注可能有误，自动筛选不能替代人工审核。

“横/竖屏筛选”可选“无”“横屏”或“竖屏”；默认无方向限制。无方向限制时最低分辨率使用正方形预设，默认 **1080 × 1080**，包含 720、768、900、1080、1200、1440、2160 和 4320 边长。横屏默认 **1920 × 1080**，竖屏默认 **1080 × 1920**。切换筛选选项时，最低分辨率都会恢复为对应默认值。最低分辨率始终按原图宽、高分别检查，不修改显示器设置。

同方向图片按主显示器比例居中裁切、缩放。原图与显示器方向相反时，完整保留图片主体并以同图模糊、压暗背景填满屏幕，避免竖图在横屏桌面上被裁掉大部分内容。壁纸缓存复用前会重新检查原图尺寸记录；缺少尺寸记录的旧缓存需要重新下载。缓存只避免重复下载图片，不决定选图顺序；榜单和作品信息每次在线获取及验证。候选数量有限，较高的分辨率门槛可能没有结果。

### 定时更新

CRON 下拉框提供常用预设，选择“自定义”后可直接输入表达式。

| 表达式 | 执行时间 |
| --- | --- |
| `*/5 * * * *` | 每 5 分钟 |
| `*/10 * * * *` | 每 10 分钟 |
| `*/30 * * * *` | 每 30 分钟 |
| `0 * * * *` | 每 1 小时 |
| `0 9 * * *` | 每天 09:00 |
| `0 9 * * 1` | 每周一 09:00 |

使用本地时区，支持五段 `分 时 日 月 星期` 或六段 `秒 分 时 日 月 星期`；日与星期遵循标准 CRON 的 OR 语义。

关闭期间错过的时刻不补执行，休眠恢复时最多执行一次。上一轮未完成时跳过新触发，不累积任务。避免使用秒级表达式持续请求，以免触发上游限流。

### 托盘与退出

标题栏最小化时窗口保留在任务栏；点击关闭会隐藏到托盘，程序继续运行。托盘不可用时关闭窗口会最小化到任务栏。点击“退出”才结束程序。

程序退出后保留最后设置的壁纸。

“开机启动”仅注册当前用户的登录启动项，不需要系统服务或计划任务。

## 网络设置

### 代理

代理统一应用于 API 和图片请求，包括启用镜像后的请求。

- **系统**：默认，读取环境代理和 Windows Internet Settings 中的手动代理，不保证支持 PAC / WPAD。
- **直连**：禁用代理。
- **HTTP/SOCKS5**：选择后在同一控件输入地址，例如 `http://127.0.0.1:7890` 或 `socks5h://127.0.0.1:1080`。

代理认证信息会明文保存在本地配置中，请勿分享包含凭据的配置文件。

### 自建镜像

“镜像”支持三种选择：

- **Pixiv 直连**：直接访问 Pixiv，不使用镜像。
- **FlashZeri + pixiv.re 中转**：排行榜和作品信息经 FlashZeri 转发，客户端图片下载使用 pixiv.re。
- **自定义**：选择后，下拉框变为可编辑状态，直接在同一控件输入镜像服务的完整地址。

镜像模式下，排行榜和作品 API 实时经 FlashZeri 转发；图片请求由镜像返回指向 `https://i.pixiv.re` 的 302，客户端随后直接下载图片内容，不经 FlashZeri 服务器。

右侧“连通性测试”使用当前镜像和代理配置，在后台检查排行榜 API 是否返回有效榜单；不会更换壁纸，也不验证图片下载是否可用。

更新设置分为队列设置（排行榜、榜单时间）、筛选设置（横/竖屏筛选、最低分辨率）、定时更新（CRON）、网络设置（镜像、代理）和启动设置（开机启动）。底部“队列下一张”只推进当前队列，不改变队列设置。手动点击“队列下一张”时，如果当前请求仍在进行，会取消并丢弃旧请求，再按当前队列重新获取下一张。定时任务在上一轮仍运行时则跳过，不累积请求。

Docker Compose 部署步骤、访问控制建议和检查命令见 [镜像部署说明](mirror/README.md)。镜像宿主机必须能访问 Pixiv，客户端必须能访问 `i.pixiv.re`。镜像不能保证绕过上游访问限制，第三方图片服务的可用性也不由本项目控制。

## 数据与卸载

数据保存在 EXE 同级的 `data` 目录；源码运行时保存在项目目录。

| 路径 | 内容 |
| --- | --- |
| `data/config.json` | 设置、最近使用记录和当前作品信息 |
| `data/wallpapers/` | 壁纸图片和原图尺寸记录 |
| `data/app.log` | 轮转日志：API 请求耗时、图片跳转、下载字节数与耗时、图片处理及整次选图耗时 |

缓存不会自动清理。删除前请确认文件不是当前壁纸。分享日志前请检查其中的作品信息、本地路径等内容。

卸载时先关闭“开机启动”，然后退出并删除程序目录。

## 开发与构建

需要 Windows 和 [uv](https://docs.astral.sh/uv/)。

```bat
run-windows.bat
```

启动源码版本。构建便携版：

```bat
build-windows.bat
```

产物位于 `dist\PixivWallpaper\`，分发时保留整个目录。仓库另提供 GitHub Actions Windows 构建工作流，支持手动触发或推送 `v*` 标签。

开发脚本将 Python、虚拟环境和缓存保存在项目目录，不向全局 Python 安装依赖，也不修改系统 PATH。测试命令：

```bat
.venv\Scripts\python -m unittest -v
```

GUI 测试需要可用的显示环境。代码按 `app.py`（界面和任务协调）、`core.py`（配置、请求、筛选和 Windows 集成）、`calendar_picker.py`（日期控件）组织，镜像配置位于 `mirror/`。

在 Windows 多显示器环境下，程序只生成并设置一张桌面壁纸，图片按主显示器尺寸处理；Windows 将该壁纸应用到桌面，不支持为各显示器选择不同作品或分别裁切。

## 限制

- 不支持动画或 Windows 幻灯片管理。
- 依赖 Pixiv 公开接口，接口变更、网络限制和限流可能导致更新失败。
- Windows 原生壁纸 API、托盘、登录启动和打包程序仍需 Windows 实机验收；镜像服务仍需 Docker/Nginx 部署验收。单元测试通过不等于完成这些平台验收。
